# jst-rwi Product Contract

jst-rwi is consumed over HTTP by the separate race-strategy repository.
This document is the binding description of that interface. The pinned
machine-readable form lives at [docs/product/openapi.v0.json](product/openapi.v0.json)
and is regenerated by `make product-schema`.

## 1. Stability tiers

Three tiers, encoded in `rwi.api.product.TIER_BY_PREFIX` and emitted on
every response as `X-Rwi-Product-Tier`:

| Tier           | Meaning                                                                                  |
|----------------|------------------------------------------------------------------------------------------|
| `stable`       | Stable **form**: field names, units, provenance structure. Versioned per §3.             |
| `experimental` | Implemented, not validated. Numbers are not production-grade; shape may still shift.     |
| `internal`     | Operator/UI/health. Not part of the product. May change without notice.                  |

**`stable` does not promise that every number is validated.** It
promises the *shape*: that a response field called `global_horizontal`
stays named `global_horizontal`, stays in W/m², stays carrying a
`Provenance` object with the same fields. Whether the number inside is
good enough to steer a race is answered by `/api/forecast-quality/*`
and by the self-knowledge section of a meteorologist briefing, not by
the tier.

## 2. The surface

### STABLE
- `GET /api/state` — vehicle position, mode, time base.
- `GET /api/meteorologist/risk-ahead | forecast-reliability | morning-briefing`  
- `POST /api/meteorologist/ask`
- `GET /api/route/{route_id}/progress | trajectory | weather`
- `GET /api/solar/position | day | clearsky | clearsky/day`
- `GET /api/weather/forecast | observations | providers | observable | variables`
- `GET /api/alerts`
- `GET /api/energy/forecast | array`
- `GET /api/forecast/archive | verification | ensemble | models`

### EXPERIMENTAL
- `GET /api/strategy/vehicle | scenarios`
- `GET /api/ml/models | bands | scores` (ADR 0008: ML quantile bands; `status: no_model` when no model is trained)

The strategy endpoints live inside jst-rwi today because the strategy
repository does not yet exist. Their numbers are not production-grade.
The strategy repo must treat them as a preview of the integration
surface, not as a decision input.

### INTERNAL
- `GET /api/validation/*` — reference-data cross-checks for operators.
- `GET /api/satellite/*` — satellite/nowcast sources (unstable upstream).
- `GET /health`, `/healthz`, …

Anything whose path does not match a listed prefix defaults to
`internal`. A new STABLE endpoint requires an explicit entry in
`TIER_BY_PREFIX` *and* a schema re-export in the same PR.

## 3. Versioning

The product version is `jst-rwi`'s package version
(`importlib.metadata.version("jst-rwi")`, canonical in `pyproject.toml`
— there is no second hardcoded copy). It appears on every response as
`X-Rwi-Product-Version`.

Semver with pre-1.0 convention:

- `0.y.0` (minor) — **breaking** for STABLE endpoints while we are pre-1.0.
- `0.y.z` (patch) — non-breaking: fields added, bugs fixed, docs edited.
- `1.0.0` — the first release where major is the only breaking lever.

A STABLE change that is intentional:

1. Edit code.
2. Bump version in `pyproject.toml`.
3. `make product-schema` → updates `docs/product/openapi.v0.json`.
4. Commit both. The pin test (`tests/unit/test_product_schema_pin.py`)
   compares current schema to pin; any delta without a conscious
   re-export is a CI failure.

## 4. Hard rules the strategy repo inherits

These are jst-rwi's correctness invariants. The strategy consumer MUST
assume them and MUST NOT undo them downstream:

1. **No synthetic value is presented as an observation.** Every number
   carries `Provenance.kind`. The strategy UI must check
   `kind != OBSERVATION` before labelling a modelled value as "measured".
2. **Every number carries provenance.** Fields are: `provider`,
   `dataset`, `kind`, `retrieved_at_utc`, `valid_time_utc`, `point`,
   `unit`, `quality`. A response without provenance is a bug — report it.
3. **UTC internally.** Local time is derived from active position via
   `timezonefinder`; never hardcoded.
4. **Sun below horizon ⇒ direct ground irradiance is exactly 0.0.**
5. **The platform recommends; humans decide.** jst-rwi never commands
   vehicle actuation. The strategy repo must not add such a command path.

## 5. Degradation contract

An endpoint whose dependency is unavailable returns HTTP 200 with the
missing piece marked:

- A `ToolResult` carries `available=false` and a `reason` string.
- A `Briefing` lists the gap under `unknowns` and the reason under
  `warnings_and_limits` instead of omitting the section.
- A list endpoint returns an empty list with the reason surfaced in the
  companion report where applicable.

HTTP 5xx is reserved for genuine bugs. A legitimate "no position yet",
"no provider online", "archive empty" is not a 5xx.

## 6. The in-tree client

`rwi.client.RwiClient` is a thin HTTP client kept here for convenience
and in-tree tests. The strategy repo may use it **while it lives in
this workspace**, but:

- The authoritative contract is the OpenAPI pin, not an import of
  `rwi.contracts`. Field changes in `rwi.contracts` that don't change
  the wire shape are not breaking.
- When the strategy repo is extracted, do not ship this client with
  `pvlib`, `numpy`, `h5py`, `earthaccess` in its dependency closure.
  Publish a slim client with its own minimal response models.

## 7. Forbidden

The strategy repo MUST NOT:

- Import anything from `rwi.core.*`, `rwi.solar.*`, `rwi.energy.*`,
  `rwi.providers.*`, `rwi.verification.*`, `rwi.archive.*`,
  `rwi.alerts.*`, `rwi.meteorologist.*`. Those are implementation.
- Call endpoints with tier `internal`.
- Depend on the numbers behind endpoints with tier `experimental`.
- Mutate archive state through any backdoor (archive writes are a
  server-side effect of `/api/weather/observations` + `/forecast` runs,
  never a client action).
